# GroomBox: backend schema

Last updated: 2026-10-27
Related: [technical requirements](trd.md), [product requirements](prd.md), [app flow](app-flow.md)

This is the design the first migrations are written from. Exact SQL lives in `supabase/migrations/` and `supabase/baseline.sql` once implementation starts.

## 1. Conventions

- Primary keys are `uuid` with `gen_random_uuid()`, named `id`.
- Every tenant table has `organization_id uuid not null` referencing `organizations`, indexed.
- Timestamps are `timestamptz`. Every table has `created_at`; mutable tables have `updated_at` maintained by a trigger.
- Money is `numeric(20,2)`. Percentages are `numeric(5,2)`.
- Time ranges are half-open, `[start_at, end_at)`.
- Status columns are Postgres enums.
- Human-readable codes (`booking_code`, `statement_code`) are generated by the database with the shared generator and a `BEFORE INSERT` trigger; inserts omit them.
- Snapshots and loosely structured metadata are `jsonb`.
- Organization and branch slugs are generated by the database in a `BEFORE INSERT` trigger: lowercase letters, digits, and hyphens, accents removed, with `-2`, `-3`, and so on added on a collision. Owners cannot edit a slug, and it does not change when the name changes, so shared links and printed QR codes keep working.
- Row-level security is enabled on every table. No table is readable or writable without a policy.

Constraints and indexes:

- Exclusion constraint preventing overlap per staff member:

  ```sql
  exclude using gist (
    staff_id with =,
    tstzrange(start_at, end_at, '[)') with &&
  ) where (
    staff_id is not null and start_at is not null
    and status in ('held', 'payment_submitted', 'needs_resubmission',
                   'review_expired_pending_resolution', 'confirmed',
                   'checked_in', 'in_service', 'completed')
  )
  ```

  Requires the `btree_gist` extension. Expired holds are moved to `hold_expired` by the create-booking function before it inserts, so they do not trip the constraint.
- Check: `end_at > start_at`; `amount_due = case when deposit_amount > 0 then deposit_amount + convenience_fee else 0 end`.
- Indexes: `(branch_id, start_at)`, `(staff_id, start_at)`, `(booked_by, start_at desc)`, `(organization_id, client_id)`, and partial indexes on `hold_expires_at` and `review_expires_at` for the statuses the jobs scan.

## 13. Row-level security summary

| Table group | Select | Insert, update, delete |
|---|---|---|
| `profiles` | Own row; members see profiles of their organization's members | Own row |
| `shop_applications` | The applicant; platform admin | Functions only |
| `organizations`, `branches`, hours, closures, media | Active members of an accessible organization | Owner; managers for their branches |
| Members, invites | Owner; a member sees their own row, even when restricted, through `my_memberships` | Owner, through functions |
| `service_categories`, `services`, `staff`, `staff_services` | Members | Owner |
| `branch_services`, `staff_branches`, `staff_shifts`, `staff_time_off` | Members | Owner; managers for their branches (time off: staff assigned to their branches) |
| `clients` | Owner, manager; staff see clients on their branches' bookings | Owner, manager |
| `bookings`, `booking_services` | Members by branch scope; the booking's creator | Functions only |
| `payment_proofs` | Permitted reviewers by branch; the submitter | Functions only |
| Sales, daily close | Owner, manager by branch; staff see their own sale items | Functions only |
| `fee_entries`, `fee_statements` | Owner, regardless of access status; platform admin | Functions only |
| `notifications` | Recipient | Recipient may set `read_at` |
| `platform_settings` | Platform admin; fee values exposed to others through booking functions; owners read GroomBox's payment instructions through `platform_payment_instructions` | Platform admin |

"Accessible organization" means `access_status = 'active'`. Membership is resolved with a set-based lookup:

```sql
organization_id in (
  select m.organization_id
  from organization_members m
  join organizations o on o.id = m.organization_id
  where m.user_id = (select auth.uid())
    and m.is_active
    and o.access_status = 'active'
)
```

Branch-scoped policies add a second lookup through `member_branches`. Policy changes are measured as an authenticated role, per the repository's RLS performance rule.

## 15. Seed data

`supabase/seed.sql` and a local seed script create, for development and tests:

- A platform admin, two owners, managers, staff with and without logins, and clients with accounts.
- Shop applications: one pending, one rejected, and the approved ones behind the seeded organizations.
- Two organizations: one with two branches, one with one branch and `restricted` access.
- Categories, services, branch offerings, staff, shifts.
- Bookings in every status, online bookings with and without a deposit, walk-in and staff-entered clients without accounts, proofs in every status, completed sales, one closed day.
- Fee entries, one paid statement, one issued, one overdue.

Seed data never goes in migrations.
